# 任务路由下 VLM 怎么训 · 8 组消融（仿真代理任务，11/12–）

> 状态：**未完成。** 代码、8 组初始权重和冒烟测试都做完了，正式训练开始后，决赛开始前没有得到评测结果。决赛的训练没有用任务路由。

## 要回答的问题

决赛只有三个固定任务，推理时任务是已知的（指令关键词就能区分）。如果让 LingBot-VLA 2.0 的动作专家在每层 MoE 用“这个任务自己的”路由器（Router，决定每个 token 交给 32 个路由专家里的哪 4 个），那视觉语言部分（VLM，这里是 Qwen3-VL）应该怎么训？

- 冻结；
- 冻结 + 一套所有任务共享的 LoRA（低秩适配器，只训很少的额外参数）；
- 冻结 + 每个任务一套 LoRA；
- 全量训练。

每种训法能不能稳定训完、能不能正常推理、三个任务的效果差多少。

## 为什么做

- 赛前方案里，“按任务路由 MoE 专家”是两条可选增强之一，思路来自 MoE-Adapters（每个任务一个路由器，复用共享的专家），见 [赛前技术方案](../../docs/pre_final/plan.md) 第 7.8 节。
- 官方的均衡损失（`per_sequence`）在每条样本内部把 token 摊匀，等于要求每个任务都均匀使用 32 个专家，和“不同任务偏好不同专家”反着来。显式的任务路由器是一种绕开的办法。
- 原计划先做零成本的诊断和“任务路由偏置”A/B；11/12 队里改成直接做“每个任务复制一个路由器”，在这个前提下比较 VLM 的训法。

## 设置

| 项 | 设置 |
|---|---|
| 起点 | 官方 LingBot-VLA 2.0 6B 底座 |
| 代理任务 | 仿真里没有决赛三个任务的示范，用 RoboTwin 2.0 clean 数据里最接近的任务代替，每个 50 条示范：T1 ← `place_a2b_left` + `place_a2b_right`，T2 ← `put_object_cabinet`，T3 ← `dump_bin_bigbin` |
| task_id | 指令关键词规则，按顺序第一个命中的算：`drawer` → T2；`pour / empty / dump / bin / trash / balls / tilt` → T3；`left / right` → T1；都没命中 → -1（用原始 Router，不加 LoRA）。在 4 个数据集的全部 20,000 条训练指令上 100% 正确 |
| Router | 36 层 MoE 每层加 3 个任务 Router，从该层预训练 Router 复制初始化；原 Router 冻结，只给 -1 用。32 个路由专家、共享专家、attention、投影都共享 |
| 动作专家 | 全量训练 |
| LoRA | 只加在 Qwen3-VL 文本层的 K/V 投影上，rank 16、alpha 32；A 用固定种子初始化（同一层在各组、各任务里相同），B 为 0 |
| 第 0 步 | 每组都和底座完全一样（新路由器是复制的，LoRA 的 B 为 0） |
| 训练 | 初赛从底座训练的配置：Muon 优化器，学习率 1e-4 → 5e-5 余弦，全局 batch 128，深度 / 视频对齐损失照旧；3000 步，第 1500 步再存一次；4 个数据集等概率采样（T1 的两个数据集合占一半）；同一随机种子 |
| 评测（计划） | 每组训完自动提交 RoboTwin 评测：demo_clean，4 个任务各 25 回合，8 组同一批种子，专家最多试 5 次；另看 loss 曲线、梯度尖峰、各任务的专家负载和重叠度 |
| 算力 | 训练只用 B200：同一组排 6 个作业按优先级接力（4 卡 > 2 卡 > 1 卡），卡数变了用梯度累积保持全局 batch 128，从最新存档接着训，每 15 分钟存一次续训点。评测在 A100 / H100 / H200 / L40S 上跑（B200 跑不了 RoboTwin 评测） |

### 8 组

| 顺序 | 组 | VLM | LoRA 层 |
|---|---|---|---|
| 1 | `E1_frozen` | 冻结 | — |
| 2 | `E4_fullsft` | 全量训练（LLM 和 ViT） | — |
| 3 | `E2_shared_mid` | 冻结 + 共享 LoRA | 第 2, 5, …, 35 层（12 层） |
| 4 | `E3_task_mid` | 冻结 + 每任务 LoRA | 同上 |
| 5 | `E2_shared_last` | 冻结 + 共享 LoRA | 28–35 |
| 6 | `E3_task_last` | 冻结 + 每任务 LoRA | 28–35 |
| 7 | `E2_shared_all` | 冻结 + 共享 LoRA | 0–35 |
| 8 | `E3_task_all` | 冻结 + 每任务 LoRA | 0–35 |

前两组最重要：E4 对应现场“先全量”的默认做法，E1 是主要替代方案（训得快，也不动 VLM）。LoRA 里跨深度的 mid 那对最有代表性，last 和 all 只比较插在哪几层。

## 结果

### 冒烟测试（单卡，每组训 10 步）：8 组全部通过

`smoke_check.py` 对每组检查三件事：

- 参数：任务 Router、动作专家、LoRA 的 B 在变；原 Router 没变；E4 以外 VLM 没变。
- 第 0 步等价：第 1 步的 loss 和原版模型完全一样（0.349304）。
- 推理：推理服务在 15 GB 显存上限下能加载，峰值约 12.1 GiB；四条测试指令（T1、T2、T3、无关指令）分别路由到 0、1、2、-1，输出是有限值；B200 上每次推理约 420 ms（不代表 RTX 5080）。

另外，`test_task_routing.py`（路由和 LoRA 选择逻辑的 CPU 单元测试）通过。

一个工程上的教训：8 组 10 步训练第一次就都跑通了，但检查脚本在 `import tensorboard` 时崩了（环境是 numpy 2，tensorboard 还在用已删掉的 `np.string_`），而它只在全部通过时才写结果文件，后台监控等了一个多小时也没报失败。之后补了 numpy 别名，每一项检查单独记录，失败也写 `failed_<arm>.json`。

> 冒烟测试里峰值显存、推理延迟和“8 组全过”这几个数字来自当时集群上的检查输出（11/12），结果文件没有放进仓库；第 1 步 loss 0.349304 是 E3_task_mid 在登录节点 CPU 上单独核对的。

### 正式训练和评测：没有结果

11/12 冒烟测试通过后，控制器按上表顺序提交了前三组（最多 3 组同时训）。B200 排队很慢，到决赛开始（11/14）前没有任何一组的评测结果，仓库里也没有之后的记录。

## 结论与状态

- **未完成，没有可用的对比结论。** 能确定的只有工程部分：任务路由补丁不设 `LINGBOT_ROUTE_CONFIG` 时和原版完全一样；8 种训法都能训、都能在 15 GB 上限下推理；第 0 步和底座等价。
- 局限：都是仿真里的代理任务，即使跑完，结论也只能用来选训练方式；用在现场需要改训练框架和推理服务里的模型代码，带额外参数的权重也要能通过平台的提交和加载。

## 在决赛中用上了什么

没有用上任务路由。决赛训练沿用官方模型结构（一份权重、没有任务 Router），三个任务混训，只把学习率分了组（从 v4 起视觉塔 ×0.1、语言模型 ×0.2，动作专家用基础学习率），见 [docs/final/training.md](../../docs/final/training.md)。

## 文件说明

| 文件 | 内容 |
|---|---|
| `code/task_routing.py` | 路由配置、关键词规则、任务 Router 的 logits、K/V LoRA、task_id 上下文 |
| `code/patch_route.py` | 把路由补丁打到一份 LingBot 代码副本上（对比实验用的代码树不动）；不设 `LINGBOT_ROUTE_CONFIG` 时和原版完全一样 |

| `code/smoke.sh`、`code/smoke_check.py`、`code/group_smoke.sh` | 冒烟测试 |
| `code/setup_groups.py`、`code/controller_route.py` | 8 个训练组（B200 接力）和登录节点控制器 |
| `code/test_task_routing.py` | 路由和 LoRA 选择逻辑的 CPU 单元测试 |
