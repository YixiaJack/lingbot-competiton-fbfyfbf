# 场景怎么布置

这份文件讲清楚仿真里三个任务的场景是怎么摆出来的：每一条规则、每一个尺寸，以及它是官方规定还是我们自己的假设。代码在 `code/`，规则全部写在 `code/scene_real.py` 里，这里的数字都是从代码里抄出来的。处理好的资产和原始文件放在一个 Hugging Face 数据集里（`<hf-dataset>`，目前未公开），不在本仓库。

## 1. 哪些是官方的，哪些是我们定的

| 项 | 依据 |
|---|---|
| 任务 1 有 36 种水果蔬菜，盘子共 10 个：白、黄、粉、紫、蓝五色，每色两个 | 官方（赛题规则，见 [docs/competition.md](../../docs/competition.md)） |
| 任务 2 有 10 件化妆品，放进三层透明收纳盒 | 官方的物品清单。收纳盒的形状和尺寸是我们假设的，开幕看实物再改 |
| 任务 3 有扫把、簸箕、红白纸团、圆筐 | 官方 |
| 绿布背景，统一的补光 | 官方（赛前培训，所有工位一样） |
| 所有物体和盘子完全可见、互不重叠，并且在执行臂可达范围内 | 官方（参考环境） |
| 机械臂是 Cobot Magic，头部一台 D435，腕部两台 D405 | 官方硬件。仿真用 RoboTwin 的 aloha-agilex，三个相机都按 RoboTwin 的 D435 设置（320×240，竖直视场角 37°） |
| 桌面高 0.74 m，盘子直径 12 cm | 我们假设的 |
| 物体可以放的范围、同侧放干扰盘、每个场景放几个物体 | 我们定的（理由见下面各节） |
| 物体按玩具大小缩放（每件的最长边在 `process_assets.py` 里定）；紧凑的物体俯视宽度不超过 6 cm，长条、弯曲或扁平的物体从厚度方向抓，不受这个限制 | 我们定的，为了让仿真里的夹爪抓得住 |

## 2. 公共设置（三个任务都一样）

- **坐标**（RoboTwin 的世界坐标）：原点在桌面中心的正下方，z 轴朝上。x 轴从机器人的视角看左负右正，x < 0 那一侧由左臂操作，x > 0 由右臂。y 轴越大离机器人越远，背景墙的前表面在 y = 0.4 m 处。
- **桌子**：长 1.2 m、宽 0.7 m、厚 5 cm，桌面高 `TABLE_TOP = 0.74` m，颜色 RGB (0.20, 0.60, 0.40)。
- **背景墙**：一面大平板，中心在 (0, 1, 1.5)，半尺寸 3 × 0.6 × 1.5 m，颜色 RGB (0.16, 0.55, 0.38)。
- **机器人和相机**：都用 RoboTwin 的 `demo_clean` 配置：aloha-agilex，不随机背景，不放杂物，桌高不随机，头部相机位置不随机，灯光固定。
- **头部相机视野**：画面不对称，右边缘在桌面 x ≈ 0.24 m 处，左边缘在 x ≈ −0.31 m 处（`VIEW_X_RIGHT = 0.24`）。所以所有物体的 x 上限都是 0.24。
- **灯光**：示范和评测场景都用固定灯光。检测器训练图有一半开了 RoboTwin 的随机灯光（`random_light`），画面会偏色或变暗。
- **资产**：每件是一个 glb，单位米，Z 轴朝上，包围盒中心在原点（`code/process_assets.py` 处理）。
  - 物体放在桌面上方 2 mm，朝向是绕 z 轴转一个角度。
  - 碰撞体是凸包。为了不让圆的水果滚走，角阻尼设 6、线阻尼设 1，质量 0.05 kg。
  - 抓取点在顶部，有 12 个方向（每 30° 一个），位置在 `assets.json` 的 `grasp_center`。这是网格的重心，不是包围盒中心：香蕉、一对樱桃的包围盒中心是空的。
- **盘子**（`build_plate`）：直径 12 cm，固定不动，网格高 0 到 1.9 cm。碰撞体是半径 4.1 cm 的圆底，加一圈 16 块倾斜的小板当盘沿（半径 5.2 cm）。

## 3. 通用的摆放规则

- **不重叠**（`sample_positions`）：每件物体用它旋转之后的轴对齐占地框，任意两件的占地框之间至少留 1.2 cm（`gap=0.012`）。采样方法是在允许的范围里随机撒点，撒不下就整体重来。
- **朝向**（`sample_yaw`）：
  - 长条的物体（最长边超过最短边两倍，比如化妆刷、香蕉、辣椒、黄瓜）大致横着放，在横向基础上随机偏 ±0.45 rad（约 ±26°），也可能正好掉头 180°。
  - 其他物体的朝向完全随机。
- **相似干扰物**（`pick_distractors` 和 `catalog.CONFUSE`）：每个场景有 1/3 的概率，先从目标所在的"长得像"那一组里挑干扰物。分组如下：

  | 组 | 物体 |
  |---|---|
  | 红色圆的 | 红苹果、红蛇果、石榴、西红柿、柿子、彩椒 |
  | 绿黄色圆的 | 青苹果、梨、柠檬、莲雾、杨桃 |
  | 橙色的 | 橙子、橘子、柿子、芒果、南瓜 |
  | 细长的 | 红尖椒、青尖椒、胡萝卜、香蕉 |
  | 绿色的 | 青瓜、青尖椒、牛油果、猕猴桃、茄子 |
  | 小而红的 | 草莓、樱桃、红苹果、火龙果 |
  | 棕色的 | 土豆、洋葱、猕猴桃、蘑菇、百香果 |
  | 刷子口红类 | 大号化妆刷、小号化妆刷、唇蜜、口红 |
  | 圆盒类 | 高光、阴影、亮片盒、粉扑 |
  | 瓶和盘 | 乳液瓶、眼影盘、唇蜜 |

- **可见检查**（`boxes(strict=True)`）：读头部相机第 0 帧的分割图，每件物体至少要有 12 个像素，并且离画面边缘至少 2 像素。不满足就换种子重摆。
  - 必须先刷新一次渲染再读分割图，否则读到的分割图里一个物体都没有（11/12 修过的 bug）。
  - 检测器训练图不做这个检查，被画面边缘切到的物体只保留看得见的部分，并标记出来。
- **稳定检查**：RoboTwin 自带的检查。摆好后物体会动的，这个种子就作废。

## 4. 任务 1：单臂抓放到指定颜色的盘子（`_layout_task1`）

**每个场景放什么**：
- 物体 `n_objects` 个，示范和评测里是 3–5 个，检测图里是 3–6 个，其中一个是目标，其余是干扰物；
- 盘子 `n_plates` 个，示范和评测里是 2–3 个，检测图里是 2–4 个。
- 盘子从"5 色×每色 2 个"这 10 个里抽：先放一个目标颜色，其余从剩下的 9 个里随机抽，所以同一种颜色可能出现两次。

**放在哪**：
- 每件物体和每个盘子的中心都在 x ∈ [−0.25, 0.25]、y ∈ [−0.16, 0.05] 内。这是 RoboTwin 单臂任务的范围（y 原本到 −0.2，我们收到 −0.16，免得近处的物体被画面下沿切掉）。
- 占地框要在 x ∈ [−0.32, 0.24]、y ∈ [−0.24, 0.12] 内。

**单臂能做完**：下面三条都满足才接受这个摆法，否则重摆（最多 1500 次，摆不下时逐步减少物体数和盘子数）：
1. 目标不能放在正中间：|x| ≥ 3 cm。目标在哪一侧，就由那一侧的手臂去做。
2. 离目标最近的那个目标颜色的盘子，必须和目标在同一侧（同号，|x| ≥ 3 cm）。专家跨过中线放就会失败，RoboTwin 自己的单臂任务也是把容器放在同侧。
3. 同一侧还要有至少一个别的颜色的盘子。这样策略不能靠"拿我这边的盘子"蒙对。

**算成功**：目标的中心在某个目标颜色盘子的圆心 5.2 cm 以内（盘子半径减 8 mm），高度在桌面到桌面以上 12 cm 之间，并且两个夹爪都松开了。同色的两个盘子放哪一个都算对。

## 5. 任务 2：化妆品放进收纳盒的指定一层（`load_actors` 里的 task 2，`build_organizer`）

**收纳盒**（我们的假设，开幕看实物再改）：三层阶梯，每层是一个上面敞开的格子。
- 宽 24 cm，每层前后深 5 cm，离机器人最近的是最下层；
- 三层底板分别高出桌面 0.4、4.4、8.4 cm，每层的围墙比自己的底板高 3.5 cm；
- 最上层另有后墙；
- 材质是透明亚克力，RGBA (0.86, 0.93, 1.0, 0.22)，透射 0.9。

**放在哪**：
- 收纳盒随机放在左侧或右侧（目的也是让单臂能做完）。右侧时中心 x ∈ [0.10, 0.115]，左侧时 x ∈ [−0.14, −0.12]，前沿 y ∈ [−0.07, −0.04]。
- 化妆品示范里 3–5 件，检测图里 3–6 件，都放在收纳盒前面：中心 y ∈ [−0.17, 前沿 − 0.03]，占地框 y ∈ [−0.22, 前沿 − 0.01]，x ∈ [−0.30, 0.24]。
- 目标化妆品和收纳盒在同一侧：中心 x 在 [0.03, 0.26]，左侧时取对称的 [−0.26, −0.03]。其他化妆品的中心 x 在 [−0.26, 0.26]。

**算成功**：目标中心落在指定那层格子的范围内，高度在这层底板上方 −5 mm 到"最长边的一半 + 2 cm"之间（立着的乳液瓶中心有 7 cm 高），并且两个夹爪都松开了。

**现状**：任务 2 的专家放不进收纳盒（细的化妆刷夹不住，高的乳液瓶会倒），所以任务 2 只有检测图，没有示范。

## 6. 任务 3：清扫（只用于检测）

- 5 件东西：簸箕、扫把、圆筐、红纸团、白纸团。圆筐固定不动，其他可以动。
- 在 x ∈ [−0.30, 0.24]、y ∈ [−0.22, 0.14] 的范围里随机摆放，互不重叠，没有别的约束。
- 指令固定是 "With the brush and dustpan, sweep up all the paper balls and empty the dustpan into the basket."
- 没有专家，也不判成功：这个任务不计识别分，我们只拿它的图训检测器。

## 7. 指令模板

`{o}` 是物体的英文名（`assets.json` 的 `name`），`{d}` 是盘子颜色或层名（bottom / middle / top）。

| 编号 | 任务 1 | 任务 2 |
|---|---|---|
| 0 | Put the {o} on the {d} plate. | Put the {o} in the {d} compartment. |
| 1 | Pick up the {o} and place it on the {d} plate. | Place the {o} inside the {d} level of the organizer. |
| 2 | Move the {o} onto the {d} plate. | Store the {o} in the {d} compartment. |
| 3 | Place the {o} on the {d} plate. | Take the {o} and put it in the {d} section. |
| 4 | Could you put the {o} on the {d} plate? | Organize the {o} into the {d} compartment. |

任务 1 的五种说法照官方给的模板；任务 2 的是我们照着写的。

## 8. 场景参数和种子

一个场景由场景参数 `spec` 加一个种子完全确定，同样的参数和种子摆出来的场景完全一样。

```python
{'task': 1, 'target': 'banana', 'dest': 'pink', 'template': 0, 'n_objects': 4, 'n_plates': 3}   # 任务 1
{'task': 2, 'target': 'lipstick', 'dest': 'top', 'template': 2, 'n_objects': 4}                  # 任务 2
{'task': 3}                                                                                     # 任务 3
```

| 用途 | 参数怎么来 | 种子 |
|---|---|---|
| 示范（`collect_real.py`，第 i 条） | 目标按物体清单轮流取；目标颜色 `PLATE_COLORS[(i // 2) % 5]`；模板 `i % 5`；物体数 `3 + i % 3`，盘子数 `2 + i % 2` | `200000 + 50i + 第几次尝试` |
| 评测（`eval_real.py`，第 i 个场景） | 目标 `T1_OBJECTS[(7i + 3) % 36]`，目标颜色 `PLATE_COLORS[(3i + 1) % 5]`，模板 `(i + 2) % 5`，物体数 `3 + i % 3`，盘子数 `2 + (i // 3) % 2` | `500000 + 50i + 第几次尝试` |
| 检测图（`det_render.py`，第 i 组的第 j 张） | 每组 20 张：任务 1 11 张、任务 2 6 张、任务 3 3 张；目标、颜色、数量都随机；奇数张开随机灯光 | 训练集 `1000i + 10j + 第几次尝试`，验证集再加 1000000 |

- 示范和评测里，同一个目标连续 12 次（评测是 20 次）摆不出专家能完成的场景，就换清单里的下一个物体做目标，换过的在 `complete.json` 里记 `target_swapped_from`。
- 评测场景的种子是提前挑好的，存在 `eval_seeds/`。之后每种对比条件都用同一批场景。

## 9. 自己摆一个看看

需要：
- RoboTwin 2.0 的代码，以及它自带的 aloha-agilex 机器人资产；
- 一张能跑 Vulkan 的 GPU（B200 不行）；
- 处理好的资产，也就是 Hugging Face 数据集里的 `assets/processed/`。

```bash
export ROBOTWIN_DIR=/path/to/RoboTwin            # RoboTwin 2.0 代码
export REAL_ASSETS=/path/to/tabletop_sim/assets/processed
export PYTHONPATH=/path/to/code:$ROBOTWIN_DIR
cd $ROBOTWIN_DIR                                  # RoboTwin 要在自己目录下运行
python /path/to/code/show_scene.py --task 1 --target banana --dest pink --n_objects 4 --n_plates 3 --seed 7 --out /tmp/scene_t1
python /path/to/code/show_scene.py --task 2 --target lipstick --dest top --seed 3 --out /tmp/scene_t2
python /path/to/code/show_scene.py --task 3 --seed 5 --light --out /tmp/scene_t3
```

每次输出三样东西：
- `frame0.png`：头部相机第 0 帧；
- `frame0_boxes.png`：同一帧加上框，白框是目标，橙框是目标盘子或目标那一层，蓝框是其他物体；
- `layout.json`：每个物体、盘子、收纳盒每一层的坐标，以及框。

在我们的 HPC 集群上（`code/runtime.sh` 里已经写好路径）不用设这些环境变量，直接 `bash code/runtime.sh sim python code/show_scene.py ...`。

**重新生成资产**：Hugging Face 数据集里有原始文件，可以从头处理一遍：

```bash
python code/process_assets.py tabletop_sim/assets/source/robotwin_subset tabletop_sim/assets/source/objaverse/glbs ./assets_out
```

`process_assets.py` 开头的 `ASSETS` 表里，每件写了来源、目标尺寸（最长边）和处理选项。要改某件的大小，改那里再重新跑一遍。

## 10. 文件索引

| 文件 | 内容 |
|---|---|
| `code/scene_real.py` | 场景本身：桌子、墙、盘子、收纳盒、三个任务的摆法、成功判定、可见检查（`boxes`）、RoboTwin 配置（`config`） |
