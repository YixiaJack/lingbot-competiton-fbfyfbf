# 目标提示的 3 色方块代理实验（11/11，已暂停）

> 状态：**暂停（11/12 凌晨），没有训练和评测结果。** 3 色方块和 3 色盘子代表不了决赛的物品和场景，起点也只有初赛的 22k+8k 模型，由 [real_detector](../real_detector/README.md) 接替。这里保留设计、代码快照和对官方代码的改动。

## 要回答的问题

在头顶相机画面上画出目标物和目的地的框（box），或者把框的坐标写进指令（coords），LingBot-VLA 2.0 第一次靠近的会不会更常是对的物体？对没见过的“物体 × 目的地”组合还管不管用？

## 为什么做

决赛任务 1、2 的识别分只看第一次靠近的物体。赛前方案（[赛前技术方案](../../docs/pre_final/plan.md) 第 6 节）想用本地小检测器在画面上标出“拿这个、放那里”，不改模型结构。动手搭决赛物品的仿真场景之前，先用最简单的代理任务把整条链路（检测 → 画框 / 写坐标 → 训练 → 配对评测）跑通。

## 设置

- **场景**（RoboTwin，aloha-agilex）：3 个方块（红、绿、蓝，边长 4.4 cm）和 3 个圆盘（黄、青、品红，半径 3.8 cm），随机放在左半边或右半边，颜色位置和指令无关。指令：`Pick up the {red|green|blue} block and place it on the {yellow|cyan|magenta} plate.`
- **数据**：120 条脚本专家示范，6 种训练组合各 20 条；红×黄、绿×青、蓝×品红 3 种组合留作泛化测试。
- **三组训练**：都从初赛的 22k+8k 权重出发（在 RoboTwin 上从官方底座从头训 22k 步、再续训 8k 步），各 2000 步、全局 batch 128、学习率 1e-5 → 5e-6 余弦：纯文本；50% 原图 + 50% 画框；50% 原指令 + 50% 坐标指令。三组用同一批轨迹和动作，只改头顶相机画面或指令。框取第 0 帧、整局不动。
- **检测器**：6 类闭集 `yolo11n`，标注直接来自仿真分割图，96 张训练、24 张验证。评测时只在第 0 帧用 CPU 检测一次；目标或目的地不确定（置信度 < 0.7，或领先第二名 < 0.15）就整局退回纯文本。
- **评测计划**（共 510 回合，全部 BF16）：底座零样本三种输入各 30 回合；三组续训后各 60 回合（已见组合 30 + 留出组合 30）；box、coords 两组各做四项补充测试（不加提示、框平移 ±10%、10% 回合给错框、YOLO 框），每项 30 回合。场景种子和策略噪声种子配对，所有物体必须完整可见。
- **首次靠近的判据**：任一夹爪中心第一次同时满足“离某个候选方块的初始位置 < 10 cm、比开局时靠近 > 4 cm、高度 z < 0.90 m”，就记为靠近了这个方块；一直没满足算错。这是代理指标，不是官方裁判的评分。
- **算力**：我的算力，8 个可抢占单卡 worker 依次领取采集、转换、检测器和评测任务；训练用排卡工具包的训练组，多种卡之间接力。

## 结果

只跑完了两项冒烟测试：

| 项 | 结果 |
|---|---|
| 场景冒烟：6 种组合的专家轨迹 | 首次靠近判据在专家轨迹上全部判对，放行后续步骤 |
| BF16 推理冒烟：22k+8k 底座、纯文本、留出组合 1 回合 | 首次靠近正确，600 步内没放成；热推理中位约 158 ms，峰值显存 12.08 GiB（在 A100 / H100 上测，不等于 RTX 5080）。记录在 `evidence/base_bf16_smoke/result.json` |

暂停前（11/12 00:23）采集到 19/120 条示范，数据转换、检测器训练、三组续训和 510 回合评测都没有开始。

## 结论与状态

暂停，没有关于“画框 / 写坐标有没有用”的结论。暂停的理由：3 色方块和盘子代表不了决赛的 36 种果蔬、10 件化妆品和透明收纳盒。接替它的 real_detector 也不再留出组合：决赛物品清单是固定的，所有物体都可以在训练里当过目标。

## 在决赛中用上了什么

没有直接用上的结果，但这里的代码是后面实验的底子：

- 画框 / 写坐标、规则解析指令、从 YOLO 结果里按“置信度 + 领先第二名”选框、没把握就退回纯文本、配对种子、首次靠近判据、按完成标记逐步放行的控制器，都原样带进了 [real_detector](../real_detector/README.md)，画框的规则后来又搬到了真机（[docs/final/inference.md](../../docs/final/inference.md)）。
- `patches/lingbot-vla-v2-dino.diff` 是我们初赛代码树相对官方 `be969b8` 的全部改动（按任务均匀采样、视觉编码器单独的学习率倍数、按时间存续训点、换卡数续训等），real_detector 和 sweep_harness 的仿真训练也用这棵代码树。

## 文件说明

| 文件 | 内容 |
|---|---|
| [代码细节.md](代码细节.md) | 每个文件怎么实现、每一步的产物、对官方代码的逐项改动说明 |
| `code/setup_experiment.py` | 生成固定设置、三组训练配置、worker 池配置、条目列表和阶段表（本身不提交作业） |
| `code/scene.py`、`code/collect.py` | 代理任务场景、仿真分割得到的真值框；采专家轨迹并校验首次靠近判据 |
| `code/cues.py`、`code/test_cues.py` | 画框、写坐标、解析指令、从 YOLO 结果里选框；单元测试 |
| `code/prepare_data.py`、`code/validate_data.py` | 同一批轨迹转成三份 LeRobot 数据，再用 LingBot 自己的数据读取器回读校验 |
| `code/train.sh`、`code/train_yolo.py` | 一组续训；训检测器、导出、测 CPU 延迟 |
| `code/server.py`、`code/eval_item.sh`、`code/evaluate.py`、`code/summarize.py` | 推理服务（每回合固定噪声种子）、配对评测、汇总 |
| `code/controller.py`、`code/runtime.sh`、`code/smoke_config.sh` | 登录节点控制器、运行环境入口、冒烟用的 worker 池配置 |
| `deps/lingbot_sampling.py` | 初赛的采样补丁（按任务均匀采样，box / coords 组因此原图和带提示的数据各占一半） |
| `patches/lingbot-vla-v2-dino.diff` | 初赛代码树相对官方 `be969b8` 的改动 |
| `evidence/base_bf16_smoke/result.json` | BF16 推理冒烟的单回合记录 |

代码里的路径是集群上的 `$SCRATCH/lingbot/...`，Slurm 账户用环境变量填，换机器要改 `ROOT`、`BASE` 和 `LINGBOT_DIR`。
