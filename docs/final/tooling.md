# 决赛：工具与看板

48 小时里同时在跑的东西很多：开发机在训练，推理机在给队友测试，数据一批批进来，几个人轮班。下面这些工具是为了让每个人随时看清现在的状态，以及在只能通过堡垒机访问的机器上可靠地操作。

## 现场看板（/field）

一个用 GitHub 账号登录的网页（Vercel 部署，代码在 [final/tools/web_board/](../../final/tools/web_board/)），给采集和换班用。

- **换班视图**（默认首页）：每 3 小时一班，自动给出"这一班该补什么"：哪个任务累计最少、上一班各任务进了多少条、哪些"目标物 × 目的地"组合还没有、目标物是不是集中在画面一边、上一班有哪些数据要复查、DAgger 占比。
- **数据覆盖**：每个任务一张桌面地图，底图是所有第 0 帧的中位数（等于空桌面），格子按目标物放过的次数着色，偏少的格子标出来。评测时裁判随机摆放，所以采集要尽量覆盖整个桌面。
- **每条数据的自动检查**：
  - 从关节和夹爪数据算出各阶段用时，标出抓空重抓、中途停顿、结束时没归位；
  - 用第 0 帧和最后一帧的检测结果判断放对了、放错位置、拿错物体还是没动。用仿真示范测过：故意把指令改成另一个物体，101 条里判出 98 条"拿错物体"，没有一条被误判成"放对了"。
- 页面只负责呈现同步进来的数据，不需要在网页上点任何东西；数据每 3 分钟自动同步一次。
- 共享的自测打分和提交检查清单存在私有的 Vercel Blob 里，写入带 ETag，多人同时保存不会互相覆盖。

## 训练看板（/train）

同一个网站的另一页，显示开发机上正在跑的训练：步数、预计结束时间、下一个存档、各项 loss 曲线、已保存的存档和大小、GPU 状态、磁盘还能存几个存档（不够时报警）、数据和配置、历次运行的状态。

数据来源：队员电脑上常驻一个脚本，保持一个堡垒机会话，每 2 分钟把一个只读探测脚本送进开发机执行，取回压缩后的 JSON，校验后推到一个私有数据仓库，网页从那里读。脚本见 [final/tools/train_board/](../../final/tools/train_board/)。

## harness 实时视图

[final/tools/harness_view/](../../final/tools/harness_view/) 是一个本地网页，通过一条只读的 ssh 连接跟踪推理机上的日志，实时显示：

- 任务三：当前子任务、发给模型的指令、大模型看到的文字和它的回复、夹爪读数和抓取网络的判断；
- 任务一、二：YOLO 画了什么框、有没有重抓；
- 复位参考（/topref）：头部相机实时画面叠上之前某一局的物体位置，用来把场景摆回和那一局一样，方便对比不同权重。任务三的历史画面取自机器人主机上的连续录制。

局域网里的队友用访问码打开；服务不写推理机上的任何文件。

## 在堡垒机后面的开发机上操作

开发机只能通过云厂商的堡垒机登录：每次登录要走一个交互菜单，没有 SFTP，空闲 10 分钟会断开。我们的做法：

- 开一个常驻的 tmux 会话登录好，之后所有命令都发进这个窗口执行，再把输出截回来（[tq.sh](../../final/tools/devmachine/tq.sh)）。脚本会先检查窗口里的 shell 确实在开发机上（会话掉线时就什么都不执行），并用锁让多个人/脚本轮流使用。
- [keepalive.sh](../../final/tools/devmachine/keepalive.sh) 每 4 分钟发一次空命令防止断开。
- 小文件双向传输用 base64 经终端传（[devget.sh](../../final/tools/devmachine/devget.sh)、[devfetch.py](../../final/tools/devmachine/devfetch.py)），大文件走 OSS。
- 教训：这个窗口是共享的，一条带 heredoc 或引号不配对的命令会让窗口停在续行提示符上，所有人的命令都发不进去；一条会读标准输入的命令会吞掉别人的命令。后来工具会拒绝在窗口不处于提示符时发送命令。

## 存档发布和提交打包

- [ckpt_guard.py](../../final/training/tools/ckpt_guard.py)：新存档写完 1 分钟后发布到 OSS，磁盘紧张时只清理旧存档的优化器状态。
- [make_submit.sh](../../final/training/tools/make_submit.sh)：生成提交目录（权重、训练代码、数据样例、日志、说明），权重两边做 SHA-256 核对。OSS 挂载盘上小文件很慢（每个约 0.5 秒），完整同步要 15–20 分钟，所以后来加了只更新权重和说明的快速模式。
- [collect_5080_inference.sh](../../final/training/tools/collect_5080_inference.sh)：给推理机上实际运行的代码拍快照。

## 第一天：在集群上复现开发机训练

决赛第一天，我们在我的算力上用同样的软件栈复现了开发机的训练（[experiments/hpc_replica](../../experiments/hpc_replica/)），验证了换数据列表续训时步数、学习率、loss 都连续，以及存档只保留 hf_ckpt 时的大小和加载方式。现场的重启方案就是基于这次验证。
