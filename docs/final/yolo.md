# 决赛：YOLO 目标检测

任务一、二的难点在识别：桌上有好几样东西，要拿对指令里说的那一个、放到指令里说的那个盘子或那一层。我们的做法是在头部画面上画框告诉模型"拿这个、放那里"（白框目标、橙框目的地），训练数据和推理时用同一套规则画（[inference.md](inference.md#yolo-框提示yolocue)）。这就需要一个能在真机画面上准确认出这些水果、蔬菜、化妆品和盘子的检测器。

## 1. 仿真训练的检测器用不上

赛前我们在仿真里搭了决赛物品的场景，训练了一个 yolo11s（[experiments/real_detector](../../experiments/real_detector/)）。拿到官方 647 条真机示范后一测：任务一里目标类别的框落在正确物体上只有 33%，任务二只有 8%，蓝色、紫色盘子都被认成白盘子。所以第一天就改成在真机数据上重新标注、重新训练。

## 2. 第一版：开放词汇模型自动标注

第一天中午，用开放词汇定位模型 LocateAnything-3B，对官方示范每条的第 0 帧按物体名字找框，再训练 YOLO。按"指令里的物体"选框，任务一 215 条里选出 157 条，和用首尾帧差分得到的真值比对，143/144 正确。这一版的带框数据进了 v2 训练。

## 3. 之后的迭代：人工核对的增量标注

第一天下午到晚上训练了 v2–v6，加入团队采集的数据。从 v7 起改成固定流程：

1. 用当前模型对新数据出候选框（`propose`）；
2. 人工逐张核对，错的写进修正表，每条都写原因（`fix*.json`）；
3. 合并成新标注（`apply`），在上一版的训练列表上加这些帧再训练；
4. 在留出集上比"选出的框对不对"，不比 mAP，因为最终用的是选框结果。

| 版本 | 新增的数据 | 主要修正 |
|---|---|---|
| v8 | 49 条新任务一示范的 150 帧 | 新留出的 16 条：13/16 对（v7a 为 11/16） |
| v9 | 0308 批次的 119 帧 | 小刷子 / 大刷子、蜡苹果 / 红蛇果、眼影盘 / 修容 |
| v10 | 修正后的官方标注 + 任务三负样本 | 和 v9 打平，没有上线 |
| v11 | 自采 87 条示范的 249 帧 | 番茄、唇釉 / 乳液、胡萝卜 / 红辣椒、亚克力后面的粉扑 |
| v12 | f64d 批次的 74 帧 | 直黄瓜被认成青椒、葡萄后面的山竹漏检、红椒被认成红蛇果 |
| v13 | 72 帧人工核对的真机画面（×8）+ 240 张复制粘贴增强 | 梨、红苹果、红蛇果、石榴、番茄、土豆；第二、三轮评测用的版本 |

同一个留出集上选框正确的条数：v7a 66/73，v8 68/73，v9 71/73，三版都没有选错物体的情况（检测不确定时就不画框）。

每升级一版，新批次的带框数据就用新版本生成，推理端换权重只需改配置文件，下一局生效。

## 4. 部署

- 推理机上没有 ultralytics，权重导出成 TorchScript，在 CPU 上跑，单次约 18 ms。
- 检测参数、选框和画框规则跟生成训练数据时完全一致，离线逐项核对过（[yolocue/README.md](../../final/inference/yolocue/README.md)）。
