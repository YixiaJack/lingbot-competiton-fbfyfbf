# 决赛：任务三的子任务调度（harness）

任务三是双臂长程任务：一只手抓簸箕、一只手抓刷子，把桌上的纸团扫进簸箕，端到筐上方倒进去，最后放下工具、双臂归位。一条示范 60–90 秒，比任务一、二长得多。

我们没有让模型用一条总指令做完全程，而是把官方的 216 条任务三示范切成 抓取 / 扫 / 倒 / 归位 四段，每段配一条固定指令来训练（[data.md](data.md#3-每批怎么处理)）。这样推理时就需要一个调度器：判断现在处于哪个子任务，把对应的指令发给模型。这个调度器我们叫 harness，代码在 [final/inference/robotharness/](../../final/inference/robotharness/)。

赛前在 RoboTwin 仿真里做过两种方案的对比（[experiments/sweep_harness](../../experiments/sweep_harness/)）：由大模型自己划分子任务，或者固定四个子任务、大模型只判断进度。真机上用的是后者。

## 1. 基本结构

- 每约 1.6 秒做一次决策：把头部和两只腕部相机的画面（各缩到 320×240）、两只夹爪的状态发给大模型（DeepSeek V4.1 Flash，通过 API 调用；key 放在推理机的环境文件里，不在仓库中），问它当前子任务是否完成、该切到哪个子任务。对话是追加式的，模型能看到之前的判断。
- 子任务之间的规则：
  - 抓取 → 扫：两只手都握住了工具；
  - 扫 → 倒：桌上的纸团都进了簸箕；
  - 倒 → 扫：倒完桌上还有纸团，回去再扫；
  - 倒完且桌上没有纸团 → 归位。
- 每次切换和每次决策都写进日志（发给大模型的文字、它的回复、当时的夹爪读数），赛后的分析都来自这些日志。

## 2. 版本演化

| 版本 | 改了什么 | 真机结果 |
|---|---|---|
| 11/14 晚 | 固定四个子任务，大模型看三路画面判断进度 | 第二轮评测用的就是这一版 |
| 11/15 下午（夹爪门控） | 用夹爪开度和关节位置判断进度：两只夹爪读数都要低于阈值才算握住，另加一条"有夹爪读数过高就否决" | 用同一个权重跑 2 局，0/2 切到扫，一直卡在抓取 65–89 秒，于是退回 11/14 版 |
| 11/16 凌晨 | 提示里加纸团描述；"握住"不再要求抬起工具；用夹爪运动历史判断握持（不依赖读数单位） | 小改动 |
| 11/16 03:06（抓取网络） | 训练一个小 CNN，从腕部画面判断这只手有没有握住工具柄 | 第三轮评测用的这一版 |
| 11/16 03:47（卡住推动） | 一只手握住、另一只手张开超过 8 秒没握住时，临时发 2.4 秒"扫"的指令让手臂动一下 | 没有效果，20 分钟后去掉 |

### 为什么夹爪门控版卡住了

11/14 版只要大模型从画面上判断两只手都握住了，就切到扫。夹爪门控版多加了两条硬条件：

- 一局里左手夹在刷毛上而不是刷柄上，读数停在 0.50，不满足阈值。大模型 23 次说"两件都握住了"，harness 一直不切，VLA 在已经拿着工具的状态下收到"抓取"指令，就停在那里不动。
- 另一局左手指尖顶在桌面上，读数 0.61，触发否决，同样卡在抓取。

而 11/14 版的 10 局里，有 4 局切到扫的时候还有一只夹爪没完全合上，结果照样扫、照样倒：VLA 在"扫"的指令下会自己把抓取补完。早一点切问题不大，硬卡着反而会卡死。

| 版本（同一个权重：总 11500 步） | 局数 | 切到扫 | 进入倒 |
|---|---|---|---|
| 夹爪门控 | 2 | 0/2 | 0/2 |
| 11/14 版 | 10 | 10/10，11.5–37 秒，中位约 16 秒 | 5/10 |

11/14 版的问题主要在后半段：纸团粘在刷毛上时大模型看不见，以为进了簸箕，于是在扫和倒之间来回切；倒之前簸箕离桌面太近就开始倾斜，纸团滚出来。后者是 VLA 的动作问题，harness 能做的只是切回扫。

还有一个细节：11/14 版直接把原始夹爪读数（0–0.1 米）发给大模型，而提示是按 0–1 的单位写的。一局里夹爪完全张开读数 0.10，大模型理解成"夹在刷柄上"，抓取和扫来回切了 4 次。

## 3. 抓取检测网络

"两只手是不是都握住了"是抓取 → 扫这一步的关键，夹爪读数靠不住：握在刷柄上和握在刷毛上读数差不多，指尖顶在桌面上会读成半开，抓空时读数是 0。所以 11/16 凌晨训练了一个小网络，直接从腕部画面判断。

- 模型：5 层 CNN，20.5 万参数。输入一张腕部画面（缩到 128×96），输出"握住工具柄"的概率。推理机 CPU 上两只手合计 1.7 ms。
- 标签从夹爪轨迹自动生成：张开之后稳定在握持区间的帧算"握住"；张开前、松开后夹爪合到底的帧和张得很开的帧算"没握住"；其余模糊的帧不用。
- 数据：官方 216 条任务三示范（每 10 帧取一帧，3.3 万张）加我们的一部分推理录像；另取 19 段推理录像做留出测试，准确率 99.8%（3211 张里 5 张误判为握住、1 张漏判）。它还能认出读数显示不出来的握持，例如刷子握在 0.07、簸箕夹在边沿 0.05。
- 网络对黑屏或噪声画面会输出接近 1，所以画面均值 < 12 或标准差 < 8 时不用它的结果。
- 接入 harness 的方式：一只手"握住" = 网络概率 ≥ 0.5 且夹爪处于合上并稳定的状态。网络说有手没握住时，大模型给出的"切到扫"最多压住 4 次。

代码：训练在 [final/inference/graspnet_train/](../../final/inference/graspnet_train/)，接入 harness 的补丁在 [robotharness/patches/patch_graspnet.py](../../final/inference/robotharness/patches/patch_graspnet.py)，模型文件在 `robotharness/graspnet/`。

## 4. 第三轮发生了什么

抓取网络本身判断得很准，但它让 harness 变得很"严格"：刷子没握住就一直发抓取指令。第三轮用的 15200 步权重恰好在抓刷子上变差了（见 [postmortem.md](postmortem.md)），10 局里有 3 局刷子一直没握住，于是整局停在抓取：

- 一局刷子手合到底什么都没夹到，之后一直张着；
- 一局刷子手两次合空，网络有一次误报，切到扫 3 秒又退回来；
- 一局刷子手张开悬了 50 秒没合。

卡住推动（第 2 节表格最后一行）就是为这种情况试的，但它只对"手指被挡住合不上"有用；"合空了"需要 VLA 张开重抓，换哪句指令都触发不了。这说明 harness 只能决定说什么，不能替模型完成动作；模型的抓取能力退化时，严格的门控会把一次失败放大成整局卡死。

## 5. 想做而没来得及做的

- 网络判断加迟滞：切到扫要求连续两次判为握住，退回抓取也要求连续两次判为没握住，可以挡住单帧误报。
- 时间兜底：扫到第 80 秒还没进入倒就强制倒，第 105 秒强制归位，保住后面几个环节的分。
- 大模型连不上时的本地兜底：用抓取网络判断抓取完成，之后按时间依次进入倒和归位。
