# 赛前技术方案

> 这是 11/14 开赛前我们定下的技术方案，由赛前的几次队内讨论、技术推演和问答合并整理而成，保留了当时的推理和取舍。**比赛中实际怎么做的、哪些计划改了、结果如何，见 [docs/final/](../final/)。** 方案背后的讨论和每个决定的来龙去脉见 [decisions.md](decisions.md)。

## 0. 结论先说

1. **主线是数据，不是改模型。** 多人轮换采集、物体位置均匀覆盖，再用人在环 DAgger（HG-DAgger，见第 7.5 节）反复迭代。
2. **一个统一模型，三个任务混在一起训。** 每一轮都带上全部历史数据，用“任务 × 阶段 × 数据来源”三级采样控制各类数据的占比，从上一轮最好的权重用低学习率热启动。
3. **两条可选增强，都要先过赛前实验的门槛才带去现场：**
   - 目标提示：用本地闭集检测器在头顶相机画面上画出目标框，不改模型结构（第 6 节）；
   - 按任务路由 MoE 专家：在一份权重里让三个任务偏好不同的专家（第 7.8 节）。
4. **推理端只加不含语言模型的东西**：规则解析指令、本地小检测器、规则类的安全模块。所有外挂都能一键关掉，退回纯 LingBot。

## 1. 背景

| 项目 | 内容 |
|---|---|
| 赛事 | 首届蚂蚁灵波具身大模型挑战赛决赛，上海，11/14–16，48 小时真机赛 |
| 机器人 | 松灵 AgileX Cobot Magic 双臂，主从臂遥操作采集；头顶一路相机加左右腕部相机 |
| 任务 | ① 单臂：把指定的水果或蔬菜放到指定颜色的盘子上；② 单臂：把指定的化妆品放进透明收纳盒的指定层；③ 双臂：一手扫把一手簸箕，把纸团扫进簸箕再倒进筐里 |
| 基座模型 | LingBot-VLA 2.0 6B，最终策略必须是它 |
| 数据 | 只能用官方公开的样例示范，加上现场在机器人上采的数据 |
| 推理 | 在本地 RTX 5080（16 GB）上跑，不接外部 API，不用 VLM 指导 |
| 训练 | 8 × RTX PRO 5000（每卡 72 GB） |

### 术语

| 词 | 意思 |
|---|---|
| VLA | 视觉-语言-动作模型：输入相机画面和文字指令，直接输出机械臂动作 |
| 动作专家（action expert） | LingBot 里负责出动作的那部分网络，接在视觉语言主干后面 |
| flow matching | 一种生成方法：从随机噪声出发，按学到的“速度场”一步步积分得到动作 |
| action chunk | 一次推理输出的一整段未来动作（LingBot 默认 50 步），执行一部分后再推理 |
| MoE | 混合专家：一层里有很多个小前馈网络（专家），路由器（router）为每个 token 挑几个来算 |
| BC | 行为克隆：直接模仿人的示范动作 |
| DAgger / HG-DAgger | 让模型自己跑，出错时人接管纠正，把纠正数据加进训练；HG（human-gated）指由人决定何时接管 |
| rollout | 让当前模型在真机上自主跑一遍 |
| 首次靠近正确率 | 机械臂第一次明显伸向的物体是不是指令要的那个；这是我们评估识别能力的核心指标 |
| BF16 / FP32 | 16 位 / 32 位浮点精度；BF16 省一半显存，但数值和 FP32 不完全一样 |

## 2. 合规边界（我们自己的理解）

| 方面 | 我们的理解 | 对方案的约束 |
|---|---|---|
| 最终策略 | 动作必须由 LingBot-VLA 2.0 6B 输出 | 外挂只能做感知预处理或安全兜底，不能替模型出动作 |
| 训练数据 | 只用官方样例和现场采集的数据 | 网上的开源数据集、网图、赛前自己采的数据都不进训练；检测器的训练图也只能来自现场相机画面或官方样例 |
| 推理 | 本地跑，不用 VLM / agent 指导，不调外部 API | 推理时“选哪个目标”不能交给任何语言模型，只能靠规则解析指令加闭集检测器 |
| 训练阶段的辅助模型 | 离线标注只产生训练标签，不进入推理链路，我们按“可接受”准备，到现场再确认 | Grounding DINO、SAM 这类带文本编码器的开源模型只在训练阶段离线打标签 |
| 不确定的地方 | 仿真数据算不算数；本地冻结小模型和 LingBot 组合成系统怎么认定；推理代码能改到什么程度 | 不依赖仿真数据；每个外挂都做成可关闭的 |

### 检测器从哪来：两手准备（11/12 定）

| 路线 | 做法 | 风险和成本 |
|---|---|---|
| 1. 赛前训好、以开源权重带去 | 在仿真里按决赛物品训好自己的检测器 | 可能被认定为绕开“赛前准备的数据不能用”；仿真里训的检测器认不认得现场实物要打问号 |
| 2. 第三方开放词表检测器 | 例如 YOLO-World：赛题词表用 CLIP 预先编码进模型，推理时不跑语言模型；到现场再用现场数据微调 | 不涉及我们赛前准备的数据；零样本能力要实测 |
| 3. 现场从公开预训练权重训 | 用现场相机画面训一个闭集 YOLO | 最稳，但约占 1 人半天的现场时间 |

当时的安排：仿真实验里同时训自己的检测器、测 YOLO-World 零样本，用同一套“按指令选框”评估比较；路线 1 用不用，等合规答复和比较结果再定。

## 3. LingBot-VLA 2.0：我们核实过的代码事实

来源是公开的官方仓库 [robbyant/lingbot-vla-v2](https://github.com/robbyant/lingbot-vla-v2)（我们初赛用的 commit `be969b8`）和 [论文](https://arxiv.org/abs/2607.06403)。

### 3.1 结构、输入和输出

| 项目 | 事实 | 对我们的影响 |
|---|---|---|
| 结构 | Qwen3-VL-4B 主干 + 稀疏 MoE 动作专家，flow matching；训练时额外蒸馏 LingBot-Depth 和 DINO-Video 的特征 | 主干是编码器用法、不自回归，推理没有 KV cache，每次推理都要做完整的去噪 |
| 相机 | 固定三路：`camera_top`、`camera_wrist_left`、`camera_wrist_right`；配置里图像输入是 224×224 | 小化妆品在 224 分辨率下只有十几个像素，细粒度识别难 |
| 状态和动作 | 统一的 55 维向量：臂关节 14、末端位姿 14、夹爪 2、灵巧手 12、腰 4、头 2、底盘 3、预留 4；不用的维度补齐 | 单臂任务里空闲臂仍在那 14 维里，只能靠采集规范让它保持不动 |
| Cobot Magic 配置 | 官方有 `agilex_cobot_magic.yaml`：臂关节动作是相对当前状态的增量（`subtract_state: true`），夹爪用绝对值 | 直接用官方配置，不改 |
| 多任务 | 论文把效果提升部分归因于多任务混合训练 | 支持三任务混训 |
| 论文里的弱项 | Cobot Magic 上的“积木分类”任务成功率 0%（π0.5 是 60%）；多个任务卡在最后的放置或松手 | “按属性选目标”和“最后放稳”正是它的弱项，也正是我们任务里的难点 |

### 3.2 推理

| 项目 | 事实 | 对我们的影响 |
|---|---|---|
| 去噪 | `modeling_lingbot_vla_v2.py` 的 `sample_actions` 里先 `noise = torch.randn(...)`，再按 `num_steps`（官方 10 步）做 Euler 积分 | **推理不是确定的**：同一个观测可能输出不同动作 |
| 随机种子 | 官方部署脚本只在进程启动时 `set_seed_everywhere(42)` | 重启服务、按同样顺序请求能复现；同一进程里每次调用的噪声都不同 |
| 动作块 | 一次出 50 步动作，部署示例执行 25 步后重新推理 | 块内动作连贯，随机性主要体现在每次重新推理时 |
| 速度 | 官方在 RTX 4090D 上一次推理约 130 ms | 5080 上要实测 |
| 精度 | 官方说明：24 GB 显卡通常要用 BF16；BF16 和 FP32 的成功率可能有明显差异，官方基准用 FP32 | 5080 只有 16 GB，**只能 BF16**；所有自测都用 BF16，和评测保持一致 |

### 3.3 训练

| 项目 | 事实 | 对我们的影响 |
|---|---|---|
| 冻结开关 | `train_expert_only: true` 加 `freeze_vision_encoder: true` 可以只训动作专家；代码在 `set_requires_grad` | 官方已有开关，不用改代码 |
| 对齐 query 的坑 | 深度、视频对齐用的 query 拼在 VLM 的输入里；只要它们还可训练，反向传播仍要穿过整个 VLM | 冻结 VLM 时要把这些 query 和蒸馏头也冻住（或关掉蒸馏损失），否则省不了多少时间 |
| 官方真机基线 | `real_robot.yaml`：Muon 优化器，lr 5e-5 恒定，global batch 256，6 万步 | Muon 的学习率尺度和 AdamW 不同，以 5e-5 为基线往下调；初赛在 RoboTwin 上续训用的是 1e-5 → 5e-6 |
| 路由专家学习率自动放大 | `use_moe_expert_lr: true` 时路由专家的学习率乘 √(32/4) ≈ 2.83；路由器和共享专家用基础学习率 | 设“动作专家 1e-5～2e-5”时，路由专家实际是 2.8e-5～5.7e-5 |
| 路由器没有单独的学习率 | 路由器和基础学习率共用一组 | 想让路由器更保守，要在 `get_moe_param_groups` 里按参数名 `.mlp.gate.` 单独分组，约 5 行 |
| **补齐的动作也参与训练** | v2 的损失没有用 `action_is_pad`（只出现在函数签名里），episode 末尾用“重复最后一个动作”补齐的 chunk 照样算损失 | 把 DAgger 接管片段切成单独 episode 还不够，片段末尾会教模型“停住”，要用帧权重屏蔽（第 7.5 节） |
| 显存和速度 | 官方示例：4 张 A6000、每卡 batch 1、开梯度检查点，每卡至少约 49 GB；8 卡 H20 每步 4.3–5.9 秒 | 72 GB 的卡每卡 batch 只能开 1–2；几千步就要几个小时，现场只够跑几次完整训练 |

### 3.4 MoE 动作专家

代码在 `qwen2_action_expert.py` 的 `Qwen2TokenMoeBlock`，配置在 `real_robot.yaml`。

| 项目 | 事实 |
|---|---|
| 位置 | 动作专家的 36 层全是 MoE |
| 专家 | 32 个路由专家（中间维 512），每个 token 选 top-4；另有 1 个共享专家（中间维 704），所有 token 都过 |
| 路由器 | `Linear(hidden → 32)`，无 bias，fp32 计算；sigmoid 打分，top-4 归一化后乘 4.0 |
| 负载均衡 | 有 DeepSeek-V3 式的无辅助损失均衡偏置，但 `bias_update_speed: 0`，等于没开 |
| 辅助损失 | 序列级均衡损失 1e-3（`per_sequence`，在每条样本内部均衡）；router z-loss 1e-4 |
| 任务信息 | 路由只看每个动作 token 自己的隐藏状态，任务信息只能通过 attention 读指令间接进来 |

## 4. 显存预算

### 推理机：RTX 5080（16 GB）

| 组件 | 估算 | 说明 |
|---|---|---|
| LingBot 6B，BF16 | 权重约 6.3B × 2 字节 ≈ 12.6 GB，加激活和运行开销约 13–14 GB | FP32 要 24 GB 以上，放不下 |
| 训练时的教师模型（MoGe、LingBot-Depth、DINO-Video） | 0 | 只用于训练蒸馏，推理不加载 |
| 检测器（每局第 0 帧跑一次） | 放 CPU，0 | 不占显存，也不拖慢控制频率 |
| 余量 | 约 2 GB | 不能再放任何大模型 |

赛前验证：在 4090 上把推理服务的显存限制到 15 GB（给驱动留余量），用 BF16 跑完整链路，记录峰值显存和延迟；到现场在真 5080 上再测一次。

### 训练机：8 × RTX PRO 5000（72 GB）

- 粗算：训练时优化器状态和梯度是 FP32，显存大约是权重的 3 倍以上，所以每卡 batch 只能开 1–2，用梯度累积凑大 batch。
- 速度按官方 H20 数据粗估，5000 步约 6–8 小时。
- 检测器训练很轻（单卡 10–30 分钟）；Grounding DINO 加 SAM 离线标注约 3–5 GB 显存。训练机要优先保证 LingBot，能不能拆出一张卡给检测器，到现场确认。

## 5. 讨论过的实验与取舍

### 5.1 逐个判断

| 想法 | 决定 | 理由和做法 |
|---|---|---|
| 检测器画框 + LingBot，看首次靠近对不对 | **做，最重要** | 识别错目标代价最大，见第 6 节 |
| 只在推理时画框，不训练 | 顺手测 | 1 小时；模型没见过带框的画面，预计没用甚至变差，测完就有定论 |
| Point-VLA 原版 | 不做原版 | 多一路图像会改变 LingBot 的三路相机输入布局和 token 顺序；论文每个任务训 2 万步、batch 512，远超现场预算。改用第 6 节的轻量版 |
| 收纳盒各层高亮 | 现场再定 | 和画框是同一套机制；仿真里没有对应场景，要看实物 |
| 测 Qwen3-VL 认不认识化妆品 | 做，30 分钟 | 用图片问 Qwen3-VL-4B，**图要先缩到 224**；只是诊断，不产出任何带进比赛的东西 |
| 5080 显存实测 | **做** | 见第 4 节 |
| 三份权重按任务切换 | 不做 | 三个 6B 在 16 GB 上放不下 |
| 一份权重里按任务激活不同 MoE 专家 | 赛前 A/B | 零初始化的任务路由偏置，只有 3,456 个参数，见第 7.8 节 |
| 关掉单臂任务里空闲臂的腕部相机 | 不做 | LingBot 没有丢相机的机制；改用采集规范：空闲臂停在同一个固定姿态，那路画面基本不变 |
| 统计物体位置分布的脚本 | 做 | 纯工具，用现场数据，找覆盖空白 |
| real2sim、仿真批量造数据、仿真里做强化学习 | 不做 | 合规不确定；现场有主从臂，真实数据价值远高于仿真；任务 3 的工具接触、纸团滚动、倾倒，仿真物理差距最大（下表） |
| 先在小 VLA 上验证画框 | 不做 | 小模型里外加视觉模块的作用会被放大，结论搬不到 6B 上；必须在 LingBot 上做 |
| 给收纳盒建模、算碰撞做运动规划 | 不做 | 执行有时间限制，而且要先从图像重建场景 |
| 加 Q 函数给候选动作打分选优 | 不做 | 要每步批量采样再打分，延迟和工程量都放不下 |
| 推理时用 Qwen-VL 兜底选目标 | 作废 | 推理时不允许用 VLM 指导 |
| 从头换架构、加深度或点云输入、换更大的模型 | 不做 | 48 小时内只做保留预训练权重的小改动 |
| 把推理改成确定的（固定种子或零噪声） | 比赛中不改 | 技术上可以，但没验证过会不会变差 |

real2sim（把真实场景重建成仿真里的数字孪生，再批量造数据）对三个任务的适合度：

| 任务 | 适合度 | 原因 |
|---|---|---|
| 1 单臂抓放 | 高 | 刚体，物体 × 盘子组合多，真机采不全 |
| 2 化妆品收纳 | 中 | 分层几何能仿真，但透明收纳盒很难渲染逼真 |
| 3 双臂清扫 | 低 | 工具接触、纸团滚动、倾倒，物理差距最大 |

即使合规，仿真画面和真实相机画面有差距，规划器生成的动作风格也和人遥操作不一样。所以这条线不投入。

### 5.2 对准失分点的小改动

| 失分点 | 改法 |
|---|---|
| 识别错目标 | 指令规范化（规则解析成标准句式）；目标提示（第 6 节） |
| 抓取、运输中掉落 | 夹爪二值化或加阈值迟滞；闭环执行，不要整块动作执行完再推理 |
| 收纳层定位不准 | 层级提示（同一套目标提示机制） |
| 双臂长流程来回重复 | 加阶段信息或本体状态历史 |
| 结束不归位 | 采集时统一归位并停稳；推理端如果允许，加完成检测和固定归位轨迹 |

### 5.3 外挂模块

都要先确认推理代码能改到什么程度；涉及语言模型的一律不用。

| 模块 | 作用 | 要不要重训 VLA |
|---|---|---|
| 起飞前自检 | 每次运行前查左右腕相机有没有接反、曝光、关节零位、推理延迟 | 不用 |
| 抓空检测 | 夹爪闭合后完全合拢说明没抓到，张开并重新推理 | 不用 |
| 卡死看门狗 | 几秒不动或原地抖动时强制重新推理 | 不用 |
| 完成检测加归位 | 判断任务完成后执行固定归位轨迹 | 不用 |
| 安全限幅 | 限制关节速度、工作空间、离桌面的最低高度 | 不用 |
| 全程记录 | 存视频、动作、检测结果，自测时自动判分 | 不用 |
| 目标高亮、层级高亮 | 第 6 节 | 要 |
| 选臂提示 | 指令后面加 “use the left arm”，消除“东西在哪边就用哪只手”带来的示范歧义 | 要 |
| 任务 3 阶段提示加纸团计数 | 状态机分步，用颜色阈值数桌上还剩几个纸团 | 要 |

## 6. 目标提示（画框）方案

### 6.1 想法和依据

识别类任务里，机械臂第一次伸向错误物体基本就救不回来，而 LingBot 恰好在“按属性选目标”上弱（第 3.1 节）。[Point-VLA](https://arxiv.org/abs/2512.18933) 的做法是在画面上把目标框出来再训练，画框把平均成功率从纯文本的 32.4% 提到 92.5%；只把框坐标写成文本，杂乱场景也能从 43% 提到 83%。它不改模型结构，只改输入和训练数据。但原版要多加一路图像、训练量也远超我们的预算（第 5.1 节），所以我们做不改结构的轻量版。

### 6.2 流程

```
评测员给的指令
   │  规则解析（模板固定，不用语言模型）
   ▼
目标物体类别、目标盘子颜色或目标层
   │
头顶相机第 0 帧（原始分辨率）──▶ 闭集检测器（CPU 上跑一次）
   │
   ▼
目标框、目的地框（盘子靠颜色阈值，收纳层按收纳盒的框按比例算）
   │
   ├─ 方案 A：把框画在头顶相机画面上
   └─ 方案 B：把框坐标追加到指令文本后面
   ▼
LingBot-VLA 2.0（结构不变）──▶ 动作
```

### 6.3 关键设计

- **不改模型结构，也不改训练代码。** 方案 A 用 ffmpeg 给头顶相机视频批量画框，生成一份数据副本；方案 B 只改数据集里的指令文本。原始数据和带提示的副本一起列进训练列表，LingBot 本身支持多数据集（`data_name: multi`）。
- **一个模型两种用法。** 带提示和不带提示的样本混合训练，同一份权重推理时加不加提示都能用。检测器没把握时不加提示，退回纯文本。
- **框错比没框更糟**，识别直接丢分，所以只在检测置信度高时加提示。
- **框什么时候撤（11/14 加的变体）。** 原方案第 0 帧的框整局不动，物体被拿起后目标框框的是空桌面。变体在夹爪闭合后去掉目标框，目的地框一直保留。夹爪“闭合”只看关节状态（离起始位置超过行程一半就算），训练数据转换和推理用同一条规则。
- **合规**：动作全部由 LingBot 输出，前面只是视觉预处理；检测器用现场画面训练，离线标注属于训练阶段的辅助。
- **前提**：推理代码允许在模型前加预处理，开幕后确认。

### 6.4 检测器怎么做

- **当闭集问题处理。** 直接下载的 COCO 预训练模型只有 80 类，没有化妆品，也没有很多赛题里的果蔬；开放词表检测器能认大类，但颜色、大小这类属性绑定差。所以现场训一个只认本次比赛物品的小 YOLO，它只负责“认东西”，动作还是 VLA 出。
- **训练图**：直接用每条采集数据的第 0 帧，不用另外拍照；目标是每类在不同位置、朝向出现 30–50 次。用 Grounding DINO + SAM 离线自动预标注，再人工修正。
- **易混的物体**：只差大小的（比如大小两把刷子）合并一类再按框长分；形状相同、只差颜色深浅的几件合并一类再按亮度和高光像素分；外观相近的果蔬先各训一类，分不开再合并加规则或小分类器；盘子直接用颜色阈值。
- **两个有利条件**：第 0 帧还没有手臂遮挡，是检测条件最好的一帧；而且不需要每个物体都认对，只需要在桌上几个候选里挑出目标类别得分最高的那个。
- **检验**：看混淆矩阵，认不准的类合并加规则；始终不可靠的类不加提示。
- **顺带的用处**：自动标注训练数据、自测时自动判断首次靠近对不对、失败归因（认错还是抓不稳）。

| 环节 | 时间和成本 |

| 赛前 | 写好指令规则解析、检测器训练流程、画框和改指令、生成带框数据副本的代码；在仿真里按决赛物品和场景做验证实验 |

### 6.6 赛前验证实验

原计划只搭一个任务 1 的简单场景。11/11 先做了一版 3 色方块的代理实验，11/12 暂停，改成按决赛物品和场景重做：

1. **场景**：RoboTwin 仿真里按决赛三个任务的物品清单搭场景，绿布背景和桌布，aloha-agilex 构型（和 Cobot Magic 一样），头顶 D435 320×240。
2. **检测器**：先训自己的 yolo11s（覆盖全部决赛物品），评估“给一条指令，能不能选对目标框和目的地框”；YOLO-World 零样本放在最后，时间够再测。
3. **对比训练**：两组都从初赛时我们在 RoboTwin 上训好的模型出发（没后训练的 6B 在仿真里什么都做不成，比不出差别），用同一批 200 条任务 1 示范各训 2000 步：纯文本组，和 50% 画框混训组（方案 A）。方案 B 因为卡不够这次没训；任务 2 因为仿真里的脚本专家放不进收纳盒，只做任务 1。
4. **测试**：60 个新布局的任务 1 场景，两组逐回合固定噪声种子配对，比首次靠近正确率。现场物品清单是固定的，所以所有物体都在训练里当过目标，不留出组合。
5. **补充测试**（都在画框组上）：不加提示、用我们 YOLO 选的框、框平移 ±10%、10% 给错框。
6. **16 GB 实测**：画框组 + YOLO 框跑 10 回合，推理服务显存限在 15 GB。初赛模型和官方 6B 同架构同大小，显存和延迟一样，不再单独拿底座测。
7. 评测一律 BF16。

**门槛**：画框组的首次靠近正确率比纯文本组高 15 个点以上，并且画框组不加提示时不变差，才带去现场；否则放弃这条线，全力做数据和 DAgger。到现场后，如果第一版模型的首次靠近正确率已经在 90% 以上，这条线也不用上。

## 7. 训练方案：渐进多任务微调 + HG-DAgger + 均衡回放

### 7.1 为什么这样训

现场数据是分批到的：开幕时只有官方的三任务样例，之后各任务的真机数据陆续采到，最后才有规模较大的完整数据集。

- **顺序训会遗忘**：先训完一个任务再训下一个，后训的任务会覆盖前面学到的东西。
- **直接追加新数据再随机训会训偏**：模型被最近采的任务主导，其他任务退化。评测是一份权重同时测三个任务，哪一项退化都直接丢分。
- **对策**：
  - 每轮保留全部历史数据；
  - 用三级均衡采样控制各类数据的占比（第 7.4 节）；
  - 每轮从上一轮验证最好的权重热启动，低学习率增量微调（第 7.6 节）；
  - 论文本身也支持多任务混训。

### 7.2 采集规范

按重要性排：

1. **先定规范再开采。**
   - 每条都从同一个默认姿态开始、回到同一个姿态并停稳（不一定是零位）。起点乱了，模型会学乱。
   - 单臂任务时，空闲臂一直停在固定姿态。
   - 指令用英文，在几种常见说法之间轮换，评测员可能用其中任何一种。
2. **识别类示范要直奔目标。** 不犹豫，不先往别的物体那边晃。易混的物体要经常同场出现，逼模型看清楚才能选对。
3. **覆盖要均匀。** 摆放的人会随便放，物体、盘子、收纳盒的位置和物体朝向都要均匀覆盖；每种物体都要当过目标，每种颜色的盘子都要当过目的地。写脚本统计头顶相机画面里的位置分布，哪里空了就补。
4. **动作质量。** 平稳、一次成功、中间不停顿；静止的帧多了模型会学成发呆（初赛我们给静止帧降过权）。放置时慢下来、稳稳松手。任务 3 抓簸箕的方式全队统一，它决定后面怎么倒。
5. **多人轮换**，每人约 100 条，动作风格多样，但抓法和顺序保持一致。
6. **安全**：开始遥操作或接管前，先把主臂和从臂对齐，否则从臂会猛地跳到主臂的位置。
7. **采坏的当场删**，并记下失败原因，作为下一轮 DAgger 的重点。
8. **采训交错**：先少量采、尽早训出 v1，用 v1 的 rollout 找失败模式，再定点补采，不平均分配真机时间。

### 7.3 训哪些参数、学习率多少

| 模块 | v1 的做法 | 说明 |
|---|---|---|
| Qwen3-VL（ViT 加 LLM） | 冻结 | 官方开关（第 3.3 节） |
| 动作专家（attention、32 个路由专家、共享专家、路由器）和 state/action 投影 | 训练 | 适配 Cobot Magic 的动作分布 |
| 深度、视频对齐 query 和蒸馏头 | 跟 VLM 一起冻住，或关掉蒸馏损失 | 否则冻结 VLM 省不了时间（第 3.3 节） |

**冻结 VLM 的风险**：任务 1、2 要靠理解指令选对目标。冻结后，“指令对应哪个物体”只能靠动作专家从现成的 VLM 特征里读，而按属性选目标本来就是 LingBot 的弱项。所以赛前在校内服务器的近似场景上实测三件事：全量微调、只冻 ViT、只训动作专家的单步耗时；只训动作专家时首次靠近正确率掉不掉；掉得明显就改成冻 ViT、LLM 用很低的学习率。

**学习率**：

| 阶段 | 设置 |
|---|---|
| v1 | 以官方 5e-5 为上限往下调；动作专家 1e-5～2e-5（路由专家实际会乘 2.83），路由器更保守（单独分组，比如乘 0.3） |
| DAgger 各轮 | 从上一轮最好的权重热启动，3e-6～1e-5 |

### 7.4 三级均衡采样

| 层级 | 初始设置 | 怎么调 |
|---|---|---|
| 任务 | T1:T2:T3 = 3:3:4 | 按各任务的真机成功率和数据覆盖情况调 |
| 阶段（技能窗口） | 抓取、运输、定位、放置、清扫、倾倒、归位 | 高价值、低频的关键操作（放置、倾倒）适当过采样，避免长时间重复动作主导训练。任务 1、2 按夹爪闭合、张开切分；任务 3 全程拿着工具，夹爪信号没用，按时间比例切或先不做。**优先级最低** |
| 数据来源 | 原始专家示范、历史成功示范、DAgger 纠正 | 第一轮 DAgger 专家 70% : 纠正 30%，中期调到 50 : 50 |

- **实现**：每个数据集对应“任务 × 来源 × 轮次”中的一格，给每个数据集一个采样概率。初赛已有一个采样补丁（按任务采样 + 每个数据集一份帧权重文件），只支持均匀和温度采样，要加一个“按文件给每个数据集指定概率”的模式，约 15 行。阶段过采样和第 7.5 节的标签屏蔽都用帧权重来做。
- **不要双重加权**：比例已经靠采样实现了，损失就不再乘同样的权重。损失保持标准 flow matching 加官方的 MoE 辅助损失。
- **退路**：如果不允许改数据加载，就在训练列表里把同一个数据集写多次（零代码），前提是验证 `data_name: multi` 接受重复条目。

### 7.5 HG-DAgger：怎么采、怎么打标签

**为什么要 DAgger**：只用示范训练的模型一犯小错，就进入训练数据里没有的状态，越错越多（误差累积）。多采示范解决不了，因为示范里都是“做得好”的状态。

**每一轮**：用当前的统一模型在真机上跑三个任务，出下面这些情况就由人用主臂接管，从模型实际到达的状态做出正确动作、完成恢复，不回到标准初始状态重新示教：

- 目标选错（识别类错误**一看到伸向错误物体的趋势就接管**，不等到救不回来）；
- 抓取偏移；
- 放置对不齐；
- 双臂协作异常；
- 清扫停滞。

| 任务 | 重点纠正 |
|---|---|
| T1 单臂抓放 | 往错误目标靠近；抓放纠正 |
| T2 化妆品收纳 | 分层定位；精细插入 |
| T3 双臂清扫 | 纸团扫偏后的恢复；双臂倾倒 |

**要记录的**：图像、机器人状态、实际执行的动作、模型预测的动作、指令、人工接管的区间、策略版本。每一帧标成“模型自主”“人工专家”“接管过渡”三类之一。

**监督标签只用人工专家动作。** 时刻 t 的样本监督的是一整段 50 步的 action chunk，这 50 步必须全是人的动作。再加上第 3.3 节的坑（补齐的动作也算损失），做法是：

1. 每段接管切成单独的 episode。
2. 去掉开头约 0.5 秒的过渡帧（主从臂对齐时的跳动）。
3. 用帧权重把最后 49 帧设成 0，保证每个样本的整段 chunk 都落在人工片段里，模型不会学到“纠正结束处停住”。
4. 接管前那段模型自己的错误动作，一律不进训练。
5. 纠正动作要平滑，风格和示范一致；先统计最常见的失败，集中纠正这些。

### 7.6 每一轮怎么迭代

1. 新采的数据（示范和 DAgger 纠正）并入统一数据池。
2. 从上一轮三任务验证最好的 checkpoint 热启动。
3. 用包含全部历史数据的混合训练集增量微调，学习率 3e-6～1e-5。
4. 分任务评估：各步骤的成功率、自主完成整个任务的成功率、人工接管频率。哪个任务掉了，下一轮就给它加采集和采样比例。
5. **按实际失败类型决定下一轮采什么。**

48 小时里大致是：先建统一的 BC 模型 v1，再做 2～3 轮 DAgger（采集、聚合、增量训练）。

**最后的巩固训练**：最后一批大规模三任务数据到齐后，用全部历史数据、全部有效纠正数据和最终新增数据做一次低学习率的联合训练，重新平衡任务、阶段和来源的占比，抵消前期顺序采集造成的偏差。最终按固定真机验证集上的三任务综合表现选权重。

### 7.7 train / val 规则

**每个阶段训两份**：A 只用 train 划分，用来定步数、配比、看做法对不对；B 用全部数据，用来提交。数据太少，提交的模型不能浪费任何一条。

- **按 episode 划分，不按帧**：相邻帧几乎一样，按帧切会泄漏。
- **按任务和布局分层**（物体 × 盘子颜色、收纳层、纸团位置），每个任务留约 10–15%，至少 3–5 条。
- **验证集固定**：进了 val 就一直在 val；之后每批新数据按同样比例补进 val，阶段之间的数字才能比。
- **A 能看出什么**：对 val episode 做开环动作误差（固定噪声种子，比较模型采样出的动作和真实动作，分任务算），用它定步数和配比，发现过拟合和任务间的互相干扰。B 用同样的做法和步数训练。
- **开环误差只是代理指标**，最后选权重看固定的真机验证集；正式评测里暴露的失败场景也要放进去。
- **算力**：A、B 串行跑时间翻倍。如果训练机能拆卡，A、B 各 4 卡并行；不能拆就只在 v1 跑 A 校准步数，之后只跑 B，改了配比、学习率或路由方式时再跑一次 A。

### 7.8 按任务路由 MoE 专家

**想法来源**：[MoE-Adapters](https://arxiv.org/abs/2403.11549)（CVPR 2024，[知乎解读](https://zhuanlan.zhihu.com/p/1915756018090119546)）研究 CLIP 的持续学习：CLIP 冻结，每层插 LoRA 当专家，每来一个新任务加一个专用路由器选 top-2 专家；学完一个任务冻结它最常用的专家；再用自编码器的重建误差判断输入属于哪个任务（DDAS）。消融显示多加路由器比多加专家有用得多。

**搬到比赛上，哪些要、哪些不要：**

| 文章里的部分 | 我们的情况 | 决定 |
|---|---|---|
| 每个任务一个路由器 | 只有 3 个任务，推理时任务已知（指令关键词就能规则区分） | 做轻量版 |
| 增量激活-冻结 | 文章里旧数据不回放才需要冻专家防遗忘；我们每轮都用全部历史数据 | 不做；只有某任务大批数据到了以后另一个任务明显退化才考虑 |
| DDAS 自动判断任务 | 任务 ID 已知 | 不做 |
| 新加 LoRA 专家 | 32 个专家已经预训练好 | 不加，复用现有专家 |

**一个现成的冲突**：官方的 `per_sequence` 均衡损失在每条样本内部把 token 摊匀。每条样本只属于一个任务，所以它等于要求每个任务都均匀使用 32 个专家，正好和“不同任务用不同专家”反着来。

**四个改动，按成本从低到高：**

1. **先诊断，不改模型。** 用 v1 或底座分别跑三个任务的 val episode，在每层路由器上挂 hook，统计 top-4 的选择分布和任务之间的重叠。三个任务已经走不同专家，显式路由的空间就小；高度重叠，后面几条才有意义。
2. **均衡损失改成全局，只改配置。** `sequence_wise_mode: "global"` 把整个混合 batch 当一条序列来均衡：总负载仍然均匀，但允许各任务偏好不同专家。系数只有 1e-3，预计影响不大，和第 3 条一起 A/B。
3. **任务路由偏置（主推）。** 每个 MoE 层加一个形状 [3, 32]、零初始化的 `task_bias`，在 sigmoid 之前做 `router_logits += task_bias[task_id]`。一共 36 × 3 × 32 = 3,456 个参数，第 0 步和底座完全一样，仍然是一份权重。训练时 task_id 由数据集映射出来；推理时按关键词规则映射（水果、盘子 → T1，化妆品、收纳盒 → T2，扫把、簸箕、纸团 → T3），认不出就用零偏置，等于底座行为，不用任何语言模型。
4. **每个任务一个路由器（文章原版）。** 把路由器复制 3 份，都从预训练权重初始化，各任务训各自那份。容量更大，但每个任务只有几十条数据，过拟合风险也更大。

不做：给每个任务硬性划一组专家（专家掩码），这会打乱预训练好的路由。

**前提**：训练框架和推理服务里的模型代码都要改，需要开幕后确认允许；带额外参数的权重要能正常提交和加载。改不了模型代码时只剩第 2 条（纯配置）。

**赛前实验**：最初设想三组同数据同步数 A/B（官方配置 / 加 global 均衡 / 再加任务路由偏置），数据按现场到达顺序模拟（比如 T1 先到、T3 后到），门槛是平均成功率提高且没有哪个任务明显变差。11/12 队内改成直接做第 4 条：每层给 3 个任务各复制一个路由器，在此基础上比较 VLM 的训法，共 8 组：VLM 冻结、全量训练、冻结加共享 LoRA、冻结加每任务一套 LoRA（LoRA 分别加在中间隔层、最后 8 层、全部层）。用 RoboTwin 里最接近的任务当三个任务的代理，在校外 GPU 集群上跑。优先级排在目标提示实验之后。

## 8. 现场节奏

### 8.1 时间线（草案）

| 时间 | 机器人 | 训练机 |
|---|---|---|
| 第 1 天上午 | 熟悉流程，按规范采集，先补官方样例覆盖不到的组合 | 用官方样例加最早一批自采数据训 v1（三任务混训） |
| 第 1 天下午 | 继续采集；如果上检测器，顺带准备检测器训练图 | v1 训练；检测器标注和训练 |
| 第 1 天晚上 | 第一次正式评测（摸清真实评测下的失败模式）；之后用 v1 rollout 做 DAgger | 训 v2 |
| 第 2 天白天 | 第一轮 DAgger，针对第一次评测的失败补数据 | v2 → 第二次正式评测 |
| 第 2 天晚上到第 3 天凌晨 | 第二轮 DAgger | 巩固训练，按截止时间提交最终模型 |
| 第 3 天早上 | 最后一次正式评测 | — |

### 8.2 正式评测怎么用

- **尽早测第一次**：尽早看到真实评测下的失败模式，之后的 DAgger 才有的放矢。
- **中间那次**用加了自采数据和第一轮 DAgger 的版本，结果指导最后一晚。
- **最后一次**：中间那次分数不错，就可以大胆一点；不理想，就交自测最稳的版本。
- **每次评测前**：提前约 1 小时冻结模型，用要提交的权重按评测方式自测，做提交前的合规自检。

### 8.3 自测怎么做

flow matching 推理有随机性（第 3.2 节）：

1. 同一个初始布局跑两次结果可能不同，每个布局多跑几次看成功率，不要看一次就下结论。
2. 比较两个模型时，每回合固定噪声种子做配对比较（初赛的 checkpoint 对比和赛前目标提示实验都是这么做的）。
3. 自测数字以多次平均为准，不靠多跑碰运气。

### 8.4 到现场先确认

1. 推理代码能改到什么程度：能不能加图像或指令预处理、规则化的归位和停止逻辑、改模型代码（任务路由偏置）和数据加载（按数据集加权、帧权重）。
2. 推理服务在 5080 上的实际精度和显存。
3. 训练机能不能拆卡（比如 7 张训 LingBot、1 张做标注和训检测器）。
4. 开发环境能不能下载开源权重（YOLO、Grounding DINO、SAM）。
5. 单臂任务里空闲臂的腕部相机和手臂怎么处理。
6. 任务 2 的收纳盒是开放的层还是要拉开的抽屉（单臂开抽屉、放入、再关上会非常难）。
7. 第一版模型出来后先测首次靠近正确率，决定目标提示这条线上不上。
