# yolocue：推理时画上训练用的 YOLO 框（11/14 晚，5080 推理服务）

- **作用**：任务 1、2 的推理会话里，在送进模型的头部相机画面上画框，跟训练数据里的一样：白框标目标物，橙框标目的地。夹爪合上后去掉白框，橙框一直保留。
  - v3（当前在评测的 `d71119c4…` 就是 v3 第 2000 步，分片哈希 `3f602582…` 对得上）训练时用了 5 个带框数据集：`public_t1/t2_box_v3`、`priv_t1/t2_box`、`priv2_t1_box`，跟同一批不带框的数据各占一半；v4 也用了带框数据。
  - 推理时以前一直没画框，所以带框的那一半训练数据从来没用上。
- **规则跟训练一样**（`autolabel/t1_boxes.py`、`t2_boxes.py`、`own_boxes_v5.py`、`derive_box_dataset.py`）：
  - 开始推理时，对最新一帧头部画面跑 YOLO，相当于训练用的第 0 帧（机械臂在原位）。检测参数跟 `dets_first.json` 相同：ultralytics 8.4 的 predict，conf 0.01，NMS IoU 0.5（8.4 的默认值，不是 0.7），输入 480×640 不补边，坐标保留 1 位小数，置信度保留 3 位。
  - 指令按官方 5+5 个模板解析出目标类别和目的地（`field_prompt_policy.PATTERNS`，物体叫法来自 `build_yolo` 的对照表，外加 private_instructions 里的别名）。
  - 目标：该类别分数最高的框，要求 ≥0.5，且比同类第二名高 ≥0.15。目的地：任务 1 取所说颜色、≥0.5、离目标最近的盘子；任务 2 取所说那层、≥0.5、分数最高的框。缺任何一个就不画。
  - 画法：PIL 画矩形 `[x1, y1, x2-1, y2-1]`，线宽 5，白色 (255,255,255)，橙色 (255,128,0)，画在 640×480 上。
  - 去掉白框的时机：任一只手的夹爪指令先超过 0.5、之后又低于 0.2，就算抓到了，按的是指令值而不是测量值。服务的调度是同步的，一个动作块执行完才拍下一帧，所以第 n 块里夹爪一合上，从第 n+1 块的画面起就没有白框。
  - 第一帧没画上框时，之后每次推理再试一次，直到开始后 3 秒或第一次抓取为止。
- **不画框的情况**（模型拿到原图，这种图训练时也占一半）：任务 3，或者指令对不上模板、物体不认识；目标没检出或有歧义；画面不是 480×640；任何报错。
- **开关**：`~/yolocue/mode`，可设 `off`（文件缺失也算 off）、`shadow`（只检测、记日志，图像不改）、`on`。每次开始推理时读一次，换档不用重启。现在是 `on`。
- **代码位置**（5080 的 `~/yolocue`）：
  - `yolocue_bridge.py`：解析、选框、画框、检测器，以及给 policy 的 preprocess/postprocess 套的包装。
  - `config.json`：权重、设备等。现在是 `weights/v5.torchscript`，跑在 CPU 上，单次约 18 ms，不占显存。
  - `weights/`：`v5.pt` 和 `export_ts.py` 导出的 TorchScript。推理环境里没有 ultralytics，torch 版本相同（2.8）。
  - `lbcmd.sh METHOD [JSON]`：调命令服务，例如 `get_status`、`load_policy`。
- **推理服务补丁**（`yc_server_patch.py`，叠在接管记录和 robotharness 两个补丁上）：
  - start() 里紧接在 robotharness 之后、控制循环开始前：检测并给 policy 装上包装；
  - stop() 时卸掉包装（reset() 也会走 stop()）；
  - serve() 时在后台预加载检测器（0.8 s）。

  每处都包了 try，出错时模型拿到原图。补丁前的备份是 `~/dagger_patch/lingbot_infer_server.py.before_yc_20261114_220208`。
- **部署记录（11/14 22:02）**：
  - 服务空闲时打补丁，然后 `kill -KILL` MainPID，systemd 8 秒后拉起。
  - **重启后模型会卸载**，要用 `bash ~/yolocue/lbcmd.sh load_policy '{"overrides":{"policy.model_path":"<hf_ckpt>"},"force":true}'` 加载回来，再轮询 `get_status` 直到 `loaded`。这次 35 秒加载回 d71119c4。
  - 实时取了一帧头部画面：jpeg、480×640，跟训练一致。
- **日志**：`logs/yolocue/<时间>_<会话>.jsonl`，记录开始、每次检测（含检测结果和原因）、抓取、结束和汇总。同目录还存图：`_cue.jpg` 是模型拿到的第一帧带框画面，`_grasp.jpg` 是抓取后的第一帧，`_nocue.jpg` 是没画框时的原图加检测框。
- **测试**：`test_yolocue.py`，在推理环境里离线跑，不碰服务。11/14 结果：
  - 训练框用的 759 张第 0 帧：检测结果和 ultralytics 生成的 `dets_first.json` 全部在容差内（置信度 ±0.003，坐标 ±0.8 px）；
  - 能解析指令的 523 条，画不画框的判断全部一致，其中 481 条坐标也完全相同，42 条差不到 1 px（只有 5 条的某条边移了 1 像素）；
  - 画框跟 `derive_box_dataset.draw` 逐像素相同（200/200）；
  - 模拟会话通过：画框、邮箱原图不被改、合夹爪后白框消失、结束时恢复原方法、shadow 模式不改图、任务 3 不画。
- **团队现场数据上的准确率**（`~/lingbot_eval` 的 team105，用差分真值）：
  - 全部：v5 画了框的 61 条中有真值的 56 条，对 51 条；
  - YOLO 没训过的保留集：画框 14 条，对 13 条；
  - 其余的没检出就不画。差分真值本身有误差，葡萄那条可能就是真值错了。
- **换 v6**：把权重 `~/lingbot_eval/weights/v6.pt` 拷到 5080，执行 `~/locany/yolo_env/bin/python ~/yolocue/export_ts.py <v6.pt> v6`，再把 `config.json` 里的 `v5` 改成 `v6`，下一次推理生效，不用重启。注意 5080 上 `runs/v6` 是第 7 轮就停掉的版本，不能用。
- **已知局限**：
  - 框只取开始那一帧，和训练一样，物体被碰走框也不跟着动；
  - DAgger 人工接管时如果是人把东西抓起来的，模型没发过合夹爪的指令，白框会一直留着，要等模型自己合一次夹爪才会去掉。
- **回滚**：先 `echo off > ~/yolocue/mode`，立刻生效，下一次推理就不画了。要彻底去掉，把备份拷回原路径，按 dagger_trace README 的方法重启，再用 `lbcmd.sh load_policy` 把模型加载回来。
