# 11/14 自采数据审计与修正

## 1. 任务之间有没有混淆（`check_provenance.py`、`check_within_task.py`）
- 对 v3 用到的 11 个数据集（1,909 条 episode），用连续两帧机械臂状态在原始数据里定位每一条的出处。三样东西全部一致：出处任务（官方看 T1_/T2_/T3_ 编号，自采看原始指令）、训练 prompt 的任务、数据集应属的任务。
- 任务 2 的化妆刷（makeup brush）全部在任务 2 的数据集里。任务 3 的拆分只用了真正的任务 3 示范：判断关键词是 `brush all`，不是 `brush`。
- 同一任务内部：改写后的 prompt 目的地 0 处不一致；物体只换成了官方叫法。YOLO 框的类别和 prompt 一致；cherries↔cherry、mandarin↔tangerine 是同义词。

## 3. 自采数据会不会拖累训练（`own_vs_public.py`）
自采进入训练的 112 条（任务 1/2/3 分别为 59/32/21）和官方 647 条比较，用训练时同样的归一化（v2 统计，meanstd，手臂动作相对当前状态，50 步动作块）：

| 指标（中位数） | 任务 1：自采 / 官方 | 任务 2 | 任务 3 |
|---|---|---|---|
| 动作超出 3σ 的比例 | 2.2% / 2.7% | 2.1% / 3.6% | 2.6% / 3.8% |
| 手臂速度 rad/s | 0.58 / 0.64 | 0.49 / 0.81 | 0.70 / 0.90 |
| 时长 s | 16.1 / 17.3 | 19.3 / 17.0 | 33.7 / 27.2 |
| 首帧亮度 | 0.42 / 0.52 | 0.37 / 0.55 | 0.43 / 0.53 |
| 首帧饱和度 | 0.38 / 0.71 | 0.37 / 0.43 | 0.40 / 0.69 |

- 没发现负面信号：
  - 归一化后没有异常值，比例还低于官方；
  - 跟踪误差、抖动、停顿和官方相近或更小；
  - 47 条“部分成功”的结束画面全部是正确的最终状态。
- 两点差异：
  - 自采示范更慢，任务 2 和任务 3 尤其明显；
  - 现场画面更暗、颜色更淡，每一条自采都落在官方范围之外。现场就是评测环境，所以自采数据最有价值。
- 风险其实在另一头：像现场的数据只占训练帧的约 12%，而 ±5% 的颜色增强弥补不了官方数据和现场的差距。
