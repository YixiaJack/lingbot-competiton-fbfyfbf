# 让 VLA 跟着框走 + 抓空/掉落保险（11/15 凌晨）

## 为什么要做
- 22:24 那次化妆刷任务：白框框住了左下角的刷子，橙框框住底层，但右臂抓的是中间的喷雾瓶。
- 01:13 那次胡萝卜任务：没画出框，因为紫盘被认成了粉盘，后来训练会话加了按颜色测量改判盘子的修正。没有框，模型就去拿了红辣椒。
- 基准测试（[box_sensitivity.py](box_sensitivity.py)，第 4000 步权重，官方任务 1 的 24 个场景 × 2 个随机种子，只看第一段动作、判断用的是哪只手）：

  | 条件 | 伸向框那一侧的比例 |
  |---|---|
  | C0 原指令、不画框（看是否伸向目标那一侧） | 83% |
  | C1 原指令、框在目标上 | 83% |
  | C2 原指令、框在干扰物上 | **17%** |
  | C3 不指名指令、框在目标上 | 81% |
  | C4 不指名指令、框在干扰物上 | **31%** |

  有原指令时，C0、C1、C2 在每个场景里选的手都完全相同，框没有任何作用。换成不指名指令后，约 6/24 个场景会跟着框换手。场景来自训练集，模型可能记住了具体场景，所以这组数只适合做重训前后的对比。

- 原因：训练里带框样本的框和指令里的物体名永远一致，模型只看文字就能把 loss 降下去，于是走了捷径。

## 训练端
[build_cue_prompts.py](../build_cue_prompts.py) 给每个带框数据集 X 生成两个只改指令文字的副本。视频直接复用，只写 meta：
- **X_named**："Pick up the {obj} in the white box and place it on the {color} plate in the orange box."（任务 2："Put the {item} in the white box into the {level} compartment in the orange box."）
  - 名字留着：白框去掉后、或者东西掉了，模型还能靠名字找到目标；同时把 "white box" 这个词和框挂上钩。
- **X_gen**："Pick up the object in the white box and place it on the plate in the orange box."
  - 只有框能告诉模型拿什么、放哪，逼它学会看框。
- 模板来自 `yolocue_bridge.cue_prompts`，和推理端是同一份代码。
- lerobot 按 `tasks.iloc[task_index]` 取指令文字，所以 tasks.parquet 里有重复的字符串也没关系。

**4500 步重启**（[v4b_switch.sh](../../../training/tools/v4b_switch.sh)）：
- 从 global_step_2500（总第 4500 步）出发，模型和优化器接上，数据加载状态从头开始。
- 列表 `lists/v4b.txt`：任务 3 占 44.7%（new1115 ×8、own_t3_sub_new1115 ×10，今天的数据权重最高），点名带框 17.8%，不指名带框 10.7%，原图任务 1/2 约 27%。
- 带框数据换成训练会话修正过的 public *_v3fix 和用 v7a 重做的 own *_v7a。

## 推理端（yolocue_bridge.py，见 [diff](yolocue_bridge_1115_cue_regrasp.diff)，还没上线）
- `cue_prompt`（默认关）：画出框时把指令换成 X_named 的写法。只有用 *_named 数据训过的权重才能打开。
- `regrasp`（默认开，只对任务 1：`regrasp_tasks: [1]`）：
  - **判断松手**：抓起之后，同一段动作里抓取那只手的夹爪指令出现"先合上、后张开"。只看同一段内部的顺序，是因为 RTC 每段开头的前缀里，可能还带着抓取之前张开的那几步。
  - **松手 1.5 秒后检测目标位置**：
    1. 有任何一个目标类的检测落在盘子里（任务 2 是收纳盒各层合起来的范围，放大 15%），就算放好，停止检查。
    2. 否则，如果这个目标类检测框和开局帧里另一个物体的框重叠（IoU > 0.5），视为没动过的相似物，不理会。
    3. 剩下的才算"东西在桌上"：把白框重画到它身上，重新等待下一次抓取。
  - 最多补救 2 次；5 秒内一直没看到目标就放弃。
- 测试：
  - [test_yc_cue.py](test_yc_cue.py) 9 项全部通过；
  - 训练会话原有的 test_yolocue.py 在新版本上 0 项失败（523 条画框判断没有一条不同，画框逐像素一致）。
- 用官方示范最后一帧测误判（[release_check_lastframes.py](release_check_lastframes.py)，YOLO v7a）：

  | | 画出框 | 判为放好 | 误判补救 | 没看到目标 |
  |---|---|---|---|---|
  | 任务 1 | 193 | 184 | 2 | 7 |
  | 任务 2 | 211 | 191 | 2 | 18 |

  剩下的 4 个误判，"桌上目标"的框和开局白框重叠 0.96–0.99：开局时 v7a 就把框画在了相似物上（百香果/红苹果、莲雾/西瓜片、唇彩/乳液瓶、高光/修容），示范里被拿走的是真正的目标。所以在开局框画对的前提下，补救规则 0 误判。这 4 个例子在训练数据里都已经是正确的框。
